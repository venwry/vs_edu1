# Aurelia Software Compatibility Kit

Launch: **COMDEX, December 3, 1979**, alongside Aurelia+, Pulse and Abacus 2.0, using the project's established conference date. AION Software supplies the kit; Logix supports the published hardware interfaces. This is a new manufacturer/integrator product, separate from the existing application-developer SDK and registration.

## Strategic transition

Logix moves new hardware development and promotion toward Aurelia+. Independent manufacturers can build Aurelia-class clones or adapt their own CP/M machines to the released application environment. Existing Aurelias continue receiving support and compatible software. This is not an immediate production shutdown, forced replacement or guaranteed support end date. Existing annual Aurelia pricing remains valid as a planning offering; precise future production allocation is not yet modelled.

Logix has no reason to block independent implementations. A bespoke partnership or mandatory certification is not required. The published interfaces, qualified applications and peripheral ecosystem make compatibility attractive. Competitors may imitate Abacus; efficient sparse storage and mature workflows provide an implementation advantage, not a permanent exclusive right to a general technique.

## Kit and optional services

- **Kit:** processor/OS/runtime and resource specifications; reference adapter source; hardware/software diagnostics; interface and failure-mode tests; Abacus and Business Tools application acceptance workloads; porting manual; results forms and certification guide. Supplied as manuals, source listings and disks. Media conversion is quoted separately.
- **Engineering support:** optional annual subscription with updates and ten remote engineering hours by correspondence/telephone. Additional hours and site visits are separately quoted.
- **Certification:** optional eight-hour assessment of a named machine/configuration, CP/M and runtime versions, application edition and test results. Failed submissions return for correction. Extra work and incremental retests are quoted separately. A passing result permits only the tested, versioned claim; relevant changes trigger scoped retesting.

Manufacturers support their own machines. Self-tests are available before paid submission. AION's directory must distinguish manufacturer-declared compatibility from AION-tested application configurations. No firm turnaround guarantee or unlimited engineering commitment is implied by the workload allowances.

## Conditions and claims

Existing Abacus binaries require compatible Z80 instruction execution and the specified OS/runtime, memory and interface behaviour. CP/M by itself is not sufficient. A different processor requires a suitable port or execution solution. Native displays, keyboards, disks and printers may be exposed through runtime adapters; neither FlexiBUS nor Logix video hardware is compulsory for application compatibility.

Keep application compatibility, FlexiBUS electrical/protocol compatibility and Logix display compatibility as separate profiles. Full Aurelia hardware clones may implement more than one profile, but one test result does not establish the others. Named supported editions in the catalog describe tested configurations, not an exclusive list of manufacturers allowed to run licensed software. Compatibility does not guarantee identical worksheet capacity on machines with different resources.

## Practical agreement model

Published specifications and self-test requirements are freely accessible. Standard kit terms permit modified reference runtime adapters to be redistributed without a per-computer royalty. Purchase of the existing commercial developer registration is not a prerequisite. Paid support and certification use separate standard agreements.

The kit does not grant redistribution rights to CP/M, Abacus, BPI applications, proprietary firmware or trademarks. Obtain the relevant licences separately; proprietary application source is not included. AION-funded ports, proprietary source access, application bundling/distribution commitments and bespoke engineering require broader agreements. An NDA applies only when confidential material is actually supplied, not to ordinary access to published interfaces.
