Why adoption accelerates—and where it slows

C and Breakthru TUI portability

Adam’s early C advocacy makes shared application logic and documented APIs the preferred design. It is a portability discipline, not a guarantee. Z80 and ERA have different integer/pointer widths, memory models and OS services. The project’s launch compiler is a documented contemporary C subset; modern ANSI C facilities are not assumed. ABI details and conformance remain engineering gates. Ordinary CP/M programs also require version, TPA, display, disk-format and BIOS qualification: a 1.4-derived core does not automatically run every later CP/M 2.x application.

Assumptions, counting rules and forecast equations

Catalogue breadth grows sublinearly with qualified active hosts and tool maturity. New TUI adoption gradually raises the portable source pool. Native ports use at least the prior quarter’s TUI pool; native-only entrants depend on the Artemis installed base. Paid copies depend on new installations plus repeat purchases from existing active hosts, then are allocated across qualified titles. Hardware sales follow the same installed-base logic, with qualification delays by device category.

New-host CP/M paid copies: 1.15 plus 0.10 per existing host/quarter; native AIONix: 1.45 plus 0.13, reduced during its launch ramp. BPI’s existing 20% Logix attachment assumption is added separately as one customer licence. Devices: 0.34 per new host plus 0.045 per existing host/quarter, with an initial supplier ramp. New external supported hosts have 35% FlexiBUS attachment. Active hosts retire at 1%/quarter. These inputs are judgments, not measured conversion rates.

After 1981, central Logix quarterly shipments grow 4%, conservative −2%, strong 8%; the native share increases 3.5 percentage points per quarter, capped at 85%. Through 1981 the scenarios share the same existing central Logix unit forecast. External OEM recruitment, title supply and purchases vary independently.
